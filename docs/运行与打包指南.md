# 运行与打包指南

## 依赖服务

> **2026-08-27**：STT/TTS 已切换到 Azure AI Speech（key + region 在 App 设置页录入），本地 stt-server/tts-server 停用（代码保留可切回）。一键启动脚本仅切回本地服务时需要。

App 运行需要先启动以下本地后端服务：

| 服务 | 目录                     | 端口 | 启动命令                   |
| ---- | ------------------------ | ---- | -------------------------- |
| STT  | `D:\project\stt-server\` | 5000 | `python server.py`         |
| TTS  | `D:\project\tts-server\` | 4000 | `node local-tts-server.js` |
| LLM  | `D:\project\llm-server\` | 3001 | `yarn start`               |

### 一键启动（推荐）

```powershell
# Windows PowerShell — 启动 STT + TTS，会自动创建/复用 venv
.\scripts\start-services.ps1

# 跳过健康检查
.\scripts\start-services.ps1 -NoCheck

# 跳过 adb reverse
.\scripts\start-services.ps1 -NoAdb
```

```bash
# WSL bash — 同上（自动调用 Windows PowerShell）
./scripts/start-services.sh
```

首次运行自动创建 Windows venv 并 `pip install` 依赖，后续秒开。按任意键统一关闭所有服务。

## 服务地址配置

所有后端服务地址集中在 `src/config.ts`，默认值如下：

```typescript
export const TTS_URL = 'http://localhost:4000';
export const STT_URL = 'http://localhost:5000';
```

- **模拟器 / USB 调试（adb reverse）** — 保持 `localhost` 即可
- **真机独立打包（无 adb reverse）** — 改为电脑的局域网 IP，手机和电脑需在同一 WiFi

## 模拟器运行

### 1. 启动 Metro

```powershell
# Windows PowerShell（Metro 不能在 WSL 中启动）
cd D:\project\cooking-guide
yarn start
```

### 2. 编译安装到模拟器

```powershell
# Metro 未启动时 — 编译 + 安装 + 启动 Metro
$env:SKIP_IOS="true"; yarn android

# Metro 已启动时 — 只编译安装，不重启 Metro
$env:SKIP_IOS="true"; yarn android --no-packager

# x86 模拟器需要时，显式覆盖默认架构（package.json 已默认 arm64Debug）
$env:SKIP_IOS="true"; yarn android --mode x86Debug --no-packager
```

> 项目分了 arm64/x86 两个 flavor，Gradle 任务名是 `installArm64Debug`/`installX86Debug`，裸跑 `installDebug` 不存在。已在 `package.json` 的 `android` script 中写入 `--mode arm64Debug`（2026-08-27，debug 主路径为 arm64 真机，见 ROADMAP）。
>
> **同类坑**：`debuggableVariants` 默认值 `["debug"]` 匹配不上带 flavor 的 variant 名（如 `arm64Debug`），导致 debug 构建被 RNPG 打成内嵌 bundle 的离线包——App 不连 Metro 也能跑，但改 JS 代码不会热更新。已在 `android/app/build.gradle` 的 `react {}` 块显式列出 `debuggableVariants` 修复（2026-08-27）。

> `SKIP_IOS=true` 跳过 `react-native-audio-api` 下载 iOS 预编译库，省几分钟构建时间。可在 PowerShell profile 中设为全局变量：
>
> ```powershell
> echo '$env:SKIP_IOS="true"' >> $PROFILE
> ```

### 3. ADB 端口转发

模拟器通过 `adb reverse` 访问宿主机上的后端服务：

```powershell
& "C:\Users\fely\AppData\Local\Android\Sdk\platform-tools\adb.exe" reverse tcp:4000 tcp:4000
& "C:\Users\fely\AppData\Local\Android\Sdk\platform-tools\adb.exe" reverse tcp:5000 tcp:5000
& "C:\Users\fely\AppData\Local\Android\Sdk\platform-tools\adb.exe" reverse tcp:8081 tcp:8081
```

或用辅助脚本（自动转发 4000/5000/8081）：

```powershell
node scripts/adb-reverse.js
```

### 4. adb 命令规范

系统 PATH 中可能有多个 adb（如 scrcpy 自带旧版本），**必须使用 Android Studio 的 adb**：

```powershell
& "C:\Users\fely\AppData\Local\Android\Sdk\platform-tools\adb.exe" <命令>
```

### 白屏排查

若 Metro 启动后模拟器白屏：

1. **重新编译安装** — 旧 APK 可能 JS 引擎从未初始化，`yarn android` 重新编译即可
2. **端口转发** — 确认 `adb reverse tcp:8081 tcp:8081` 已执行
3. **Reload** — 模拟器中 Ctrl+M → Dev Menu → Reload
4. **查看日志** — Android Studio Logcat 过滤 `ReactNative` 或 `com.cookingguidern`

## 真机无线调试（WiFi ADB，2026-08-27 实测打通）

无需 USB 线，手机与电脑同一 WiFi 即可。Android 11+ 使用系统「无线调试」：

```powershell
# 1. 配对（手机：开发者选项 → 无线调试 → 使用配对码配对设备）
#    小窗里显示的 IP:端口 + 6位配对码；配对端口配对完成后即关闭
adb pair 192.168.1.xxx:<配对端口>

# 2. 连接（端口用「无线调试」主界面显示的那个，与配对端口不同！）
adb connect 192.168.1.xxx:<主界面端口>
adb devices                            # 应看到 192.168.1.xxx:xxxxx device

# 3. 端口转发（每次重连后需重新执行）
adb -s 192.168.1.xxx:<端口> reverse tcp:8081 tcp:8081
```

实测要点：

- **配对与连接是两个不同端口**，connect 用配对端口会报 10061 拒绝
- **双设备条目坑**：`adb devices` 出现同一手机两条（`IP:port` + `adb-xxx._adb-tls-connect._tcp`）时，`adb reverse` 会静默失效（手机上 curl localhost:8081 可通但 App 连不上）。先 `adb disconnect adb-xxx._adb-tls-connect._tcp` 只留一条，再重新 reverse
- **adb 用 Windows 侧**（`C:\Users\fely\AppData\Local\Android\Sdk\platform-tools\adb.exe`）；WSL 是 NAT 网络且未装 adb，不要在 WSL 里搞无线调试
- **Metro 必须跑 Windows PowerShell**（WSL NAT 下手机访问不到 WSL 的 8081）；手机端也可在 Dev Menu → Settings 设 Debug server host = 电脑IP:8081 替代 reverse
- **debug 包只在启动/Reload 瞬间需要 Metro**：bundle 拉到手后 Metro 挂了页面照常跑；改代码/重启 App 时才需要重新连

## 真机独立打包

无需插电脑、无需 Metro 热重载，打包成独立 APK 安装到手机。

> **已验证**：STT（语音命令识别）+ TTS（语音播报）真机调试已通过（2026-06-17）。手机和电脑在同一 WiFi 下即可正常使用。

### 1. 改服务地址

```powershell
# 查电脑局域网 IP
ipconfig
```

修改 `src/config.ts`：

```typescript
export const TTS_URL = 'http://192.168.x.x:4000';
export const STT_URL = 'http://192.168.x.x:5000';
```

> 电脑和手机需在同一 WiFi 下，电脑上需先启动好后端服务。

### 2. 打包

```powershell
cd D:\project\cooking-guide\android
.\gradlew assembleRelease
```

APK 生成位置：`android/app/build/outputs/apk/release/app-release.apk`

### 3. 安装

USB 线连手机 → 手机通知栏选择「文件传输 (MTP)」→ 电脑上把 APK 拖入手机 Download 目录 → 手机上用文件管理器点击安装。

## 分架构打包

在 android/app/build.gradle 中：
android {
flavorDimensions "arch"

    productFlavors {
        arm64 {
            dimension "arch"
            ndk {
                abiFilters "arm64-v8a"
            }
            applicationIdSuffix ".arm64"
            versionNameSuffix "-arm64"
        }
        x86 {
            dimension "arch"
            ndk {
                abiFilters "x86_64"
            }
            applicationIdSuffix ".x86"
            versionNameSuffix "-x86"
        }
    }

}

## 常见坑

| 问题                                                         | 原因与解决                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `yarn android` 失败 — `sdk.dir` 格式错误                     | `android/local.properties` 中 `sdk.dir` 必须使用 Windows 路径（如 `C:\\Users\\...`），不能用 WSL 路径（如 `/mnt/c/...`）                                                                                                                                                                                                                                                                                             |
| iOS 预编译库下载卡住构建                                     | 已通过 `SKIP_IOS=true` 环境变量拦截。`scripts/clean-ios-deps.js` 在 `postinstall` 钩子中自动执行，检测 Windows 时删除 iOS/macOS 预编译库                                                                                                                                                                                                                                                                             |
| 从 WSL 运行构建命令                                          | **不要从 WSL 运行** `yarn install` / `yarn android` / `yarn start`。这些命令必须在 **Windows PowerShell** 中手动执行。WSL 不配置 Android SDK 和 JDK，且文件路径转换会导致问题                                                                                                                                                                                                                                        |
| 构建报 `Could not find method jcenter()`（keep-awake 等库）  | node_modules 与 `patches/` 不同步（`patch-package` 未跑）。手动执行 `npx patch-package` 后重新构建；`yarn install` 的 postinstall 会自动应用                                                                                                                                                                                                                                                                         |
| `npx patch-package` 报 `Filename too long`（audio-api 包）   | audio-api 的 `build/`、`.cxx/` 构建缓存路径超长。且该包下载的 `.so/.a` 产物绝不能进 patch（否则重装时 patch 创建已存在文件导致 install 失败）。**固定用**：`npx patch-package react-native-audio-api --include "scripts/"`（只收脚本改动；遇长路径报错先删 `node_modules\react-native-audio-api\android\build` 和 `.cxx`）。该包补丁内容：Android 构建只下载 android.zip + jniLibs.zip，不再拉 4 个 iOS/macOS 无用包 |
| `yarn android` 报 `installDebug not found`                   | 多 flavor 项目无裸 `installDebug` 任务。已在 `package.json` android script 写入 `--mode arm64Debug`；x86 模拟器用 `yarn android --mode x86Debug --appId com.cookingguidern.x86`                                                                                                                                                                                                                                      |
| 构建成功但 `Error type 3: Activity class ... does not exist` | arm64 flavor 带 `applicationIdSuffix .arm64`，实际包名是 `com.cookingguidern.arm64`，CLI 默认启动无后缀包名导致。已在 android script 写入 `--appId com.cookingguidern.arm64`；手动启动用 `adb shell am start -n com.cookingguidern.arm64/com.cookingguidern.MainActivity`                                                                                                                                            |
| debug 包改 JS 不生效 / 不连 Metro 也能跑                     | `debuggableVariants` 未匹配到带 flavor 的 variant 名，RNPG 把 debug 构建打成了内嵌 bundle 离线包。已在 `android/app/build.gradle` 的 `react{}` 显式列出修复                                                                                                                                                                                                                                                          |
| 无线调试 App 连不上 Metro（curl 通但 App 红屏）              | `adb devices` 存在同手机双条目（IP 条目 + mDNS TLS 条目），reverse 静默失效。`adb disconnect adb-xxx._adb-tls-connect._tcp` 后重新 reverse                                                                                                                                                                                                                                                                           |
| `yarn android --no-packager` 时还触发 Gradle 重新下载 iOS 库 | 确保当前 PowerShell 窗口中设置了 `$env:SKIP_IOS="true"`。建议加到 PowerShell profile：`echo '$env:SKIP_IOS="true"' >> $PROFILE`                                                                                                                                                                                                                                                                                      |
| 新增原生依赖后 App 白屏/崩溃                                 | Phase 4 新增了 `react-native-haptic-feedback`、`react-native-keep-awake`、`@react-native-community/blur`，必须重新编译：`cd android && .\gradlew clean` 后 `yarn android`                                                                                                                                                                                                                                            |
| WiFi 延迟抖动影响语音                                        | 2.4GHz 网络下 STT/TTS 偶有延迟抖动，建议使用 5GHz WiFi                                                                                                                                                                                                                                                                                                                                                               |
