# 厨房 AI 助手 — 架构与技术文档 V1

## 1. 产品定位

厨房里的 AI 副厨。耳机为主交互方式，语音引导用户完成烹饪每一步。双手不离锅，耳朵听指令。

---

## 2. 系统架构总览

```
┌─────────────────────────────────────────────┐
│              React Native App                │
│                                             │
│  ┌──────────┐  ┌──────────┐  ┌───────────┐ │
│  │ 菜谱模块  │  │ 烹饪引导  │  │ 交互层    │ │
│  │          │  │  (FSM)   │  │           │ │
│  └──────────┘  └──────────┘  └───────────┘ │
│                                             │
│  ┌──────────────────────────────────────┐   │
│  │         本地存储 (SQLite)              │   │
│  └──────────────────────────────────────┘   │
└──────┬─────────────────────────────┬────────┘
       │ HTTP (adb reverse)          │ HTTP
┌──────▼──────────┐    ┌─────────────▼──────┐
│   stt-server    │    │    llm-server      │
│  (localhost:5000)│   │  (localhost:3001)   │
│  faster-whisper  │    │  DeepSeek 代理       │
└─────────────────┘    └──────────┬──────────┘
                                   │
                                   ▼
                               DeepSeek
```

架构原则：**大模型不参与实时决策**。录入时处理一次，烹饪时全程本地 FSM 驱动。

## 3. 模块划分

### 3.1 菜谱模块

负责菜谱的录入、解析、存储、编辑。

**录入入口**

| 方式     | 技术实现                                       |
| -------- | ---------------------------------------------- |
| 手动输入 | 表单 UI                                        |
| 截图识别 | 图片 → Claude Vision → 结构化 JSON             |
| 链接导入 | URL 抓取 → Claude 解析正文 → 结构化 JSON       |
| 语音录入 | Whisper STT → 文本 → Claude 解析 → 结构化 JSON |

**大模型一次性处理（录入时）**

输入任意形式的菜谱文本/图片，输出标准结构：

```json
{
  "name": "红烧肉",
  "ingredients": [{ "name": "五花肉", "amount": "500g" }],
  "steps": [
    {
      "id": 1,
      "text": "五花肉切块，冷水下锅焯水",
      "tag": "wait_timer",
      "duration_seconds": 180,
      "sub_steps": []
    },
    {
      "id": 2,
      "text": "加入生抽",
      "tag": "instant",
      "duration_seconds": null,
      "sub_steps": []
    }
  ]
}
```

**子步骤标签规则**

| 标签         | 含义                   | 行为                         |
| ------------ | ---------------------- | ---------------------------- |
| `instant`    | 放调料等快速操作       | 3-5 秒后自动播下一步         |
| `wait_user`  | 翻炒均匀等需判断的操作 | 等用户主动确认               |
| `wait_timer` | 炖煮/腌制等计时操作    | 启动计时器，到时 AI 主动提醒 |

标签由大模型在录入时一次性打好，烹饪过程中不再调用大模型判断。

### 3.2 烹饪引导模块（核心）

**FSM 状态设计（XState）**

```
IDLE
  └─[开始烹饪]→ ANNOUNCING_STEP
                  └─[播报完成]→ 根据 tag 分流
                                  ├─ instant → WAITING_AUTO（3-5秒计时）─[REPEAT]→ ANNOUNCING_STEP（重播，延迟重置）
                                  ├─ wait_user → WAITING_USER（等确认）→ ANNOUNCING_STEP
                                  └─ wait_timer → WAITING_TIMER（倒计时）→ ANNOUNCING_STEP
                                                      ├─[计时结束]→ ANNOUNCING_REMINDER → ANNOUNCING_STEP
                                                      ├─[下一步/NEXT]→ ANNOUNCING_STEP（跳过计时）
                                                      └─[再说一遍/REPEAT]→ ANNOUNCING_STEP（重播，本步骤重新计时）

任意状态:
  ├─[用户提问] → ANSWERING（单次 LLM 调用）→ 回到当前状态
  ├─[双击/再说一遍] → ANNOUNCING_STEP（重播当前步）
  ├─[跳步] → ANNOUNCING_STEP（跳到目标步）
  └─[退出] → IDLE
```

**响应时延目标**

| 操作         | 目标延迟                   | 实现方式                           |
| ------------ | -------------------------- | ---------------------------------- |
| 耳机按键响应 | <50ms                      | 本地 FSM 状态切换                  |
| TTS 首帧播出 | 云端 REST 非流式，首包较慢 | Azure AI Speech + 下一步预缓存抵消 |
| 临时提问回答 | 1-3s                       | 单次 LLM 调用                      |

**临时提问上下文结构**

```
系统提示：你是烹饪助手，用户正在做[菜名]。
当前步骤：第3步 - 大火翻炒3分钟。
用户问题：[用户输入]
要求：简短回答，30字以内，回答后用户继续烹饪。
```

### 3.3 交互层

**四种交互方式优先级与实现**

```
优先级1：耳机按键（BLE HID）
  单击 → next / confirm
  双击 → repeat
  长按 → 进入提问模式

优先级2：语音指令（Whisper STT，持续监听）
  关键词：好了 / 下一步 / 再说一遍 / 等一下

优先级3：屏幕按钮
  全屏大按钮，单手可操作

优先级4：挥手手势（MediaPipe HandLandmarker，本地推理）
  仅在无耳机连接时启用
  掌心朝前挥动 → next
```

**自动检测逻辑**

```javascript
// 伪代码
if (bluetoothHeadset.connected) {
  mode = 'headset'; // 耳机按键 + 语音同时监听
} else if (micPermission) {
  mode = 'voice'; // 语音 + 屏幕按钮
  gesture.enable(); // 同时启用手势作为补充
} else {
  mode = 'touch'; // 纯屏幕按钮
}
```

### 3.4 本地存储（SQLite）

**表结构**

```sql
-- 菜谱主表
CREATE TABLE recipes (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  cover_image BLOB,
  servings INTEGER,
  is_favorite INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER,
  updated_at INTEGER
);
-- 迁移：is_favorite 为后补列。老安装由 init.ts 在建表后用 PRAGMA table_info
-- 检测缺列并 ALTER TABLE 补列（幂等），旧数据默认 0（未收藏）。

-- 食材表
CREATE TABLE ingredients (
  id TEXT PRIMARY KEY,
  recipe_id TEXT REFERENCES recipes(id),
  name TEXT,
  amount TEXT,
  sort_order INTEGER
);

-- 步骤表
CREATE TABLE steps (
  id TEXT PRIMARY KEY,
  recipe_id TEXT REFERENCES recipes(id),
  step_number INTEGER,
  text TEXT,
  tag TEXT CHECK(tag IN ('instant','wait_user','wait_timer')),
  duration_seconds INTEGER,
  sort_order INTEGER
);

-- 烹饪记录（为 V2 复盘预留）
CREATE TABLE cook_sessions (
  id TEXT PRIMARY KEY,
  recipe_id TEXT REFERENCES recipes(id),
  started_at INTEGER,
  finished_at INTEGER,
  completed INTEGER DEFAULT 0
);
```

## 5. 数据流

### 菜谱录入流

```
用户输入（文字/图片/链接/语音）
  → [若语音] stt-server（faster-whisper）→ 文本
  → llm-server → DeepSeek（结构化解析 + 子步骤拆分 + 打标签）
  → 标准 JSON
  → SQLite 持久化
  → 菜谱列表展示
```

### 烹饪引导流

```
用户选择菜谱
  → 从 SQLite 加载步骤数据（含标签）
  → XState FSM 初始化
  → 循环：
      FSM 推进到下一步
      → 文本 → Local TTS 服务 → 音频流 → 耳机/扬声器播放
      → 根据 tag 决定等待方式
      → 用户触发（按键/语音/手势/按钮）
      → FSM 状态转换
      → 继续循环
  → 烹饪完成 → 写入 cook_sessions（为 V2 复盘预留）
```

### 临时提问流

```
用户长按耳机键 / 说"我想问个问题"
  → STT 录音 → stt-server 转写
  → FSM 进入 ANSWERING 状态（暂停计时器）
  → 携带当前步骤上下文 → llm-server → OpenAI/Claude
  → 回答文本 → TTS 播报
  → FSM 回到提问前状态（恢复计时器）
```

## 6. 后端服务

两个独立通用服务，分别部署在同一开发机上。模拟器通过 `adb reverse` 暴露端口给 Android 模拟器，真机通过局域网 IP 直连（STT + TTS 真机调试已通过）：

### stt-server（Python / localhost:5000）

通用语音转文字服务，不包含任何业务逻辑。

```
POST /v1/audio/transcriptions    → faster-whisper 本地推理
GET  /health                     → 健康检查
```

### llm-server（Node.js / localhost:3001）

通用 LLM 代理，透传 OpenAI Chat Completions 格式。支持 DeepSeek。

```
POST /v1/chat/completions        → 转发至 DeepSeek（OpenAI 兼容格式）
GET  /health                     → 健康检查
```

配置方式：在 `llm-server/.env` 中设置 `DEEPSEEK_API_KEY=sk-...`。
未设置 API key 时自动降级为 mock 模式（返回番茄炒蛋示例）。
API Key 仅存在于 llm-server 服务端环境变量中，客户端不可见。

详细实现见 `llm-server/` 目录及 README。

## 8. 关键风险与对策

| 风险                         | 概率 | 对策                                             |
| ---------------------------- | ---- | ------------------------------------------------ |
| 耳机 BLE 兼容性差异          | 中   | 优先适配 AirPods，其他耳机降级到语音模式         |
| Azure TTS 网络抖动           | 低   | 预缓存下一步 TTS 音频                            |
| Claude 解析菜谱结构不稳定    | 中   | 固定 JSON Schema + Function Calling 强制输出格式 |
| MediaPipe 手势误触发         | 中   | 设置置信度阈值 >0.85，且仅在无耳机时启用         |
| stt-server / llm-server 起停 | 低   | 开发时常驻终端进程，配合 adb reverse 使用        |
