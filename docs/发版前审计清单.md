# 发版前审计清单

> **可复用审计 SOP**。每次发版前按此清单执行，结果登记在文末审计记录表。目的：固定审计镜头，让发现逐轮收敛，而不是每次换视角出现"新问题"。
> 与一次性报告的区别：本清单是资产，报告是快照（见 [`代码审计-2026-09-02.md`](代码审计-2026-09-02.md)）。

---

## 发版就绪标准（Definition of Done）

满足全部条件才可发版：

1. **Blocker 清零**（当轮审计 blocker 全部修复并验证）
2. **门槛内 Warning 清零**（每轮审计时标记哪些 warning 属于发版门槛，默认 W 级可带病发版但须登记为已知问题）
3. **门禁四件套全绿**：`yarn lint` / `npx tsc --noEmit` / `yarn format:check` / `yarn test:all`
4. **真机冒烟通过**：录入→烹饪→计时提醒→语音控制→完成，中英文各一轮；覆盖安装升级一轮；离线烹饪一轮
5. **审计记录表当轮无未处置的 blocker/warning**（修复或明确决策"带病发版"均算处置）

> 发版 ≠ 零缺陷。发版 = 零 blocker + 已知问题清单受控。

## 一、质量门禁

- [ ] `yarn lint` 零输出
- [ ] `npx tsc --noEmit` 零错误
- [ ] `yarn format:check` 通过
- [ ] `yarn test:all` 全绿

## 二、设计系统一致性

- [ ] 硬编码颜色零残留：`grep -rnP "#[0-9a-fA-F]{3,8}\b|rgba?\(" --include="*.tsx" --include="*.ts" src/ | grep -v theme/`
- [ ] fontSize 硬编码清点：`grep -rnE "fontSize:\s*[0-9]" --include="*.tsx" src/`
- [ ] 自定义 fontFamily 扫描：全 App 已决策改用系统字体（2026-09-05，根因见 UI 规范字体节），`grep -rn "fontFamily" --include="*.tsx" --include="*.ts" src/ | grep -v theme/` 应为零且 typography.ts 内无 fontFamily；新增文字样式禁止指定 fontFamily
- [ ] 新增 UI 组件走共享组件库（Button/Card/HeaderBar/Icon），无平行手搓实现（人工抽查当轮新增组件）

## 三、死代码与孤儿代码

- [ ] 孤儿导出扫描（自研脚本思路：列 export → grep 引用 → 排除定义文件；注意区分"内部自用应去 export"与"真孤儿"）。**扫描范围必须含根目录 App.tsx 与 index.js 入口文件**（2026-09-02 教训：漏扫入口导致 ErrorBoundary/cleanupOrphanCovers 误报孤儿）
- [ ] 依赖使用扫描：逐个 dependencies 包名 grep import；`react-native-screens`、`react-native-worklets` 等 native/peer 依赖不算未使用
- [ ] TODO/FIXME/HACK 清点，逐项确认是否发版阻塞

## 四、类型纪律

- [ ] `any` 零：`grep -rnP ":\s*any\b|<any>" --include="*.ts" --include="*.tsx" src/ | grep -v __tests__`
- [ ] `@ts-ignore/@ts-expect-error` 零
- [ ] as 断言清点（排除 `export { default as X }` 惯用语法），逐处判断是否边界解析必要

## 五、React 范式（人工定向）

- [ ] 资源型副作用 cleanup 全覆盖——重点文件：录音/VAD（src/services/stt.ts、voice-commands.ts）、计时器（src/services/timer.ts）、keep-awake、音频焦点
- [ ] 新增 useEffect 依赖数组正确性
- [ ] 竞态：录入/AI 编辑等异步写入路径（历史曾修「录入竞态」，同类场景复查）

## 六、架构边界

- [ ] FSM 边界：UI 层不绕过状态机直接改烹饪状态
- [ ] 事务红线：**多表写入必须 withTransaction**——重点：screen 层直接组合 db 函数的调用点（B3 教训：db 层入口遵守不代表 screen 层遵守）
- [ ] ID 生成统一 generateUuid，无 Date.now+random
- [ ] 循环依赖扫描：`npx madge --circular src/` 零输出（2026-09-02 盲区转入；db/migrations 注释已记录一处已知边界，新增循环依赖即违规）

## 七、i18n 完整性

- [ ] 非注释中文残留：`grep -rnP "[\x{4e00}-\x{9fff}]" --include="*.ts" --include="*.tsx" src/ | grep -v __tests__ | grep -v i18n/`——逐条判断是注释（允许）还是用户可见文案（违规）
- [ ] 服务层 throw 的 message 语言（上轮 W3：错误文案硬编码中文）
- [ ] 英文模式冒烟（真机，UI + 语音 + LLM 三链路）

## 八、运行时验证（静态审计的天然盲区）

- [ ] 真机冒烟五步流程（中英各一轮）
- [ ] 覆盖安装升级（DB 迁移 + 数据保留）
- [ ] 离线场景（本地菜谱烹饪可用，网络功能优雅降级）
- [ ] 长时烹饪稳定性（keep-awake、音频焦点抢占）
- [ ] 当轮 Blocker / 关键 Warning 真机复验（B1/B2 教训：运行时行为静态审计只能给线索，结论必须真机验证）
- [ ] 性能 profile：启动耗时、列表帧率、烹饪长驻内存（2026-09-02 盲区转入，此前从未 profile）

## 九、安全与隐私

- [ ] 日志无密钥/无用户语音内容（上轮 W7）
- [ ] console.log 清点，发版清理或接 debug 开关
- [ ] android 权限最小化复查（AndroidManifest.xml）
- [ ] iOS 原生侧复查：Info.plist 权限/声明最小化、签名配置、pbxproj 引用一致性（指向不存在文件的死引用，2026-09-05 字体清理教训；本项目暂不构建 iOS，启用前必须全项过一遍）
