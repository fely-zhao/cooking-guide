## Blocker（4 项）

### B1 — TTS 音色设置是装饰品（用户选择零效果）

- **证据链**：
  - 选项仅 `minimax-female` / `minimax-male`（src/screens/SettingsScreen.tsx:23-25）
  - 写入路径 `update('ttsVoiceId', id)`（SettingsScreen:342）→ MMKV（src/services/storage.ts:39）
  - 播放消费路径为 `getVoiceConfigForText(input.text).ttsVoiceId`（src/hooks/useCookingFsm.ts:42），由 voiceMap 按文本语言硬映射（晓晓/Jenny），不读设置值
  - `MiniMaxTTSProvider`（src/services/tts-provider-minimax.ts）全库无实例化；运行时仅 `new AzureTTSProvider(...)`（src/hooks/cooking-machine-shared.ts:69）
- **修复方向（待 fely 拍板）**：推荐删除设置页音色选择器，音色完全由 voiceMap 自动决定（现有交互本来就是正确设计）；或补 Azure 音色列表并接线消费

### B2 — FSM ANSWERING invoke 无 onError（LLM 失败卡死）

- **证据**：src/machines/cooking-machine.ts:405-436，invoke 仅有 onDone 分支；llmService reject（服务未起/断网）时 FSM 停在 ANSWERING，仅 EXIT 可退出
- **关联**：ROADMAP 待解决区既有记录，本轮代码复核属实；与提问功能整体设计绑定
- **修复方向（待 fely 拍板）**：发版版隐藏 ASK 入口可降级为非问题；或补 onError 降级回原状态

### B3 — RecipeEditScreen 多表写入未包 withTransaction（违反红线）

- **证据**：src/screens/RecipeEditScreen.tsx:142-166，保存 = updateRecipe + deleteIngredientsByRecipe + deleteStepsByRecipe + 循环 createIngredient/createStep，无事务包裹
- **后果**：中途失败留下无食材/无步骤的半损菜谱
- **修复方向**：参照 src/db/recipes.ts 的 insertRecipe 用 withTransaction 包裹（或下沉为 db 层函数）

### B4 — ~~ErrorBoundary 组件零引用，App 未挂载~~【误报撤销】

- **2026-09-02 复核**：App.tsx 已挂载 ErrorBoundary（包裹 NavigationContainer，含插画兜底 UI 与重试按钮）。原审计孤儿扫描脚本只扫 src/，未覆盖根目录 App.tsx，导致误报。其余孤儿结论已在 App.tsx/index.js 逐一复核，均不受影响。
